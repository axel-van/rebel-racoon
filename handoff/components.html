Conversation thread — component handoff

Visual reference of every component that renders inside the .session__assistant-thread on /session/:id. Each card shows a live preview, the canonical HTML, the BEM classes in use, and the DS tokens that drive the chrome. Use this as a starting point when implementing any new variant — copy the HTML, swap content, and the styles cascade for free.

Source: src/screens/session.js (renderTurn dispatch) + src/assistant.js (turn types) Styles: styles/chat.css + styles/screens/session.css DS: @agorapulse/ui-theme + @agorapulse/ui-symbol

0. Decision matrix — which turn type?

Every renderable thread message hits a single dispatcher: renderTurn(message) in src/screens/session.js (~ln 756). It branches on message.role and message.variant. Use this table to pick the right shape before composing markup — the render function names match exactly so you can grep them.

message.role message.variant Render function Component Section
"assistant" — renderTurn() default branch .chat-bubble--ai §2
"user" — renderTurn() default branch .chat-bubble--user §2
"source-intake" — renderSourceIntakeTurn() .chat-bubble--source-intake §2
"assistant" "extraction" renderExtractionTurn() .extraction-turn__idea-card §5
"assistant" "draft" renderDraftTurn() .drafts-card §6
"assistant" "clip-extraction" renderClipExtractionTurn() .clip-extraction-card §7
"assistant" "idea-extraction" renderIdeaExtractionTurn() .clip-extraction-card (bulb icon) §7
"assistant-choice" — renderChoiceTurn() .chat-bubble-choices §4
"system" "mermaid" or unset renderSystemNotice() .assistant-notice §8
"pending" — renderExtractingNotice() .extracting-notice §8
Lifecycle. Stores in src/assistant.js mutate the message list (per-session Map(sessionId → turns[])). Every mutation reruns renderTurn for the touched message in place — so a source-intake turn with status: "loading" flips chrome to status: "ready" simply by updating the same object. The renderer reads live state (e.g. renderClipExtractionTurn reads the current sources-stream source to derive pending / ready / gone), which is why clip cards can transition without a new message being pushed.

Easing tokens (styles/tokens.css)

Token Value Use for

Responsive behavior

Viewport Behavior
Desktop (default) Thread column is centred at max-width: 740px via .session__assistant-thread > *; turn max-widths (560 / 480 / 420) apply on top.

Internationalisation

French copy / long translations. The codebase mixes English UI and French in comments. Strings ship from src/screens/session.js hard-coded. When a label runs ~30–40% longer (German, Russian) three components need re-checking:
  • .drafts-card__sub-text — ellipsis already handles overflow.
  • .clip-extraction-card__title — ellipsis handles it.
  • .chat-bubble-choice-chip — chips wrap onto a second row (flex-wrap) but labels themselves don't truncate. A 25-char label will widen the chip noticeably.
