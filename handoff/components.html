Conversation thread — component handoff

A visual gallery of the components that render inside the .session__assistant-thread on /session/:id. Every preview is rendered live by importing the app’s own renderers — the shared pure functions in src/screens/session/thread-turns.js and src/screens/_analyse-common.js (the same ones session.js uses). Markup and styles both cascade from src/ + styles/, so this page can never drift from the app. Inspect a preview in dev tools for the full markup.

Source: src/screens/session.js (renderTurn dispatch) + src/assistant.js (turn types) Styles: styles/chat.css + styles/screens/session.css DS: @agorapulse/ui-theme + @agorapulse/ui-symbol

1. Turn wrappers

Every message in the thread is wrapped in a .chat-turn. The variant modifier sets alignment (left/right), avatar position, and whether the children inherit a bubble or stand alone as cards.

.chat-turn--ai

AI message — sparkle avatar on the left, content beside it. No bubble chrome.

.chat-turn--user

User message — right-aligned You label stacked over a solid blue bubble.

.chat-turn--ai.chat-turn--extraction / .chat-turn--clip-extraction

AI turn with NO sparkle avatar — the child card has its own leading glyph (pen, sparkles, bulb, file). Stacks vertically and gets a max-width.

Note on max-width. .chat-turn no longer carries a generic max-width. Only .chat-turn--user (560px) and .chat-turn--extraction (480px) are bounded. Other AI turns flow at the thread's natural width (740px via .session__assistant-thread > *).

2. Bubbles (AI / User / Source intake)

The bubble wraps the message body. AI bubble is borderless — text sits directly next to the sparkle avatar, no chrome. User bubble is a solid blue card. Source intake is a light-blue file-attachment card aligned with the user.

.chat-bubble--ai

Borderless AI bubble. Defensive reset on background/border/padding so a card child can’t accidentally inherit chrome.

.chat-bubble--user

Solid electric-blue card. Sharp top-right corner points at the user "avatar".

.chat-bubble--source-intake

Single-line compact chip with a kind icon, filename (ellipsis-truncated), and a trailing status pill. Three trailing states: loading (muted grey pill + inline dot), ready · N ideas (electric-blue pill, clickable, chevron nudges 2px on hover), ready · no ideas (bare green check). Shown user-side.

6. Drafts result — not rendered inline

Draft batches are intentionally not surfaced as an inline thread card anymore. Drafts can finish while the user is doing something else, so a card here would interleave the conversation unpredictably. The batch message stays in the thread only as the anchor for the Drafts panel; “ready” is surfaced via a toast + the persistent topbar Drafts count.

Removed component. The old .drafts-card summary (pen icon · network glyphs · .drafts-card__nets / .drafts-card__chevron) is gone — those classes no longer exist in styles/ or src/. renderTurn() returns an empty string for variant: "draft". The live, current result-card family (clips / ideas ready, pending, unavailable) lives in §7 below, rendered by the shared renderResultCard().

7. Result card — all states

Every “result of a long AI job” in the thread is one component: .drafts-card (§6), rendered by renderResultCard(). Drafts, clips and ideas share the ready state; the two transient states are modifiers on the same card — .drafts-card--pending (dot-grid loader tile) and .drafts-card--unavailable (source removed). The old .clip-extraction-card family is gone.

.drafts-card--pending

In-progress state — shared dot-grid loader in a transparent tile + “Cutting your clips…”. Non-interactive (a <div>, not a button).

.drafts-card — ready state

Done state: full-card button, mermaid tile, chevron CTA — identical for clips, ideas and drafts.

.drafts-card--unavailable

The source backing this card was removed. Muted file-icon tile, dimmed (opacity 0.65), no CTA.

8. Notices (mermaid, extracting)

Lightweight status pills posted into the thread by the assistant. Mermaid = AI work (the “Thinking” / “Drafting” reasoning chip). Extracting = inline pill + spinner for non-blocking work. (A neutral grey variant exists in the scaffold but the app never posts one — every live notice is mermaid.)

.assistant-notice--mermaid

Foldable mermaid pill — toggle reveals a grey-05 card with the detail text. Used for “Drafting” / “Extracted N ideas”.

.extracting-notice

Inline pill + spinner shown while a non-blocking extraction is running. Dissolves once status flips to ready.

9. Quick picker (inline question)

A one-question picker that overlays the composer. Built by renderPicker() and driven by inline-question.js. Same chrome, five modes — all previews below are rendered live from the real renderPicker(), so they never drift. Header carries an optional title, step label, subtitle, and back arrow.

.analyse__options — single select

Numbered rows; click jumps straight to the choice (chevron affordance).

.analyse__options--multi — multi select

Rows toggle on/off (check affordance); a Continue button submits the set.

.analyse__options--stepper — counters

Each row carries a − N + counter (0 opts out); the submit shows the summed total. Title + subtitle, and a Back button in the footer. Used by the "drafts per angle" step.

.analyse__option--input — free text

Trailing row swaps to a text input + send button for a typed answer.

.analyse__option--file — dropzone

Trailing row becomes a click/drop file zone (wraps a hidden file input).

10. Chat-switch skeleton

Shown for ~340ms inside .session__assistant-thread when switching to a different chat, then swapped for the real thread (a synchronous innerHTML swap, so the real content never flashes first). Only a started conversation is covered — the empty hero, wizard, and Clip Studio layouts are skipped. Driven by showSwitchSkeleton in src/screens/session.js; respects prefers-reduced-motion (no shimmer).

.thread-skeleton

Alternating assistant (grey, left) / user (electric-blue, right) bubble placeholders with a staggered shimmer. Bubble widths vary to read as natural copy.
